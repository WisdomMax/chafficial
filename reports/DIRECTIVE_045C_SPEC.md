① 보고서의 터널 실행 명령에는 접근 제한이 없어.

실제로 제시한 명령은 다음과 같아.

Bash
cloudflared tunnel --url http://127.0.0.1:8501

이 명령은 기본적으로 주소를 아는 사람이 접속할 수 있는 임시 터널이야. 내부 로그인 화면이 있더라도 이것을 Cloudflare 이메일 인증이 적용된 터널이라고 부르면 안 돼.

공식 문서상 이메일 제한을 적용하려면 --allowed-mail 옵션이 필요해. 
Cloudflare Docs

② 현재 설치된 cloudflared 2026.7.3 버전도 확인해야 해.

Cloudflare가 이메일 보호 Quick Tunnel 기능을 발표한 날짜는 2026년 10월 2일이야. 현재 보고된 설치 버전은 그보다 이전 버전이므로, 실제로 --allowed-mail 옵션을 지원하는지 확인하고 필요하면 업데이트해야 해. 
Changelog

③ CF-Connecting-IP 헤더를 무조건 신뢰하면 안 돼.

Cloudflare를 거쳐 온 요청에서는 유용한 헤더지만, 로컬 앱이 직접 받은 요청에서도 아무 검증 없이 신뢰한다면 로그인 횟수 제한을 우회할 위험이 있어. 신뢰할 수 있는 프록시 경로로 들어온 요청에서만 사용하도록 해야 해. 
Cloudflare Fundamentals docs

즉, 9개 테스트가 통과했다고 해서 외부 접속 보안까지 100% 검증된 것은 아니야.

1. 핵심 지시

REPORT 045-B의 로컬 실행 및 인증 테스트 결과를 접수한다.

그러나 실제 외부 접속 및 이메일 접근 제한 검증은 아직 완료되지 않았다.

이번 지시에서는 신규 업무 기능을 만들지 않는다.

목적은 차마트 웹사이트를 외부 노트북이나 스마트폰에서 인증 후 사용할 수 있게 만드는 것이다.

보고서 작성보다 실제 브라우저 접속 검증을 우선한다.

2. Cloudflare 버전 및 옵션 확인

보고된 설치 버전:

cloudflared 2026.7.3

Cloudflare 공식 문서에서는 2026년 10월 2일 이메일 인증 보호 Quick Tunnel 기능을 발표했다.

공식 자료:

https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

다음을 순서대로 수행하라.

설치된 cloudflared 버전 확인.

실제 CLI 도움말에서 --allowed-mail 지원 여부 확인.

미지원이면 안정 버전으로 업데이트 가능한지 확인.

업데이트 후 해당 옵션을 다시 확인.

실제 인증 테스트 없이 보호 기능이 동작한다고 주장하지 말 것.

사용자 동의가 필요한 관리자 권한 변경이나 유료 계정 작업은 수행하지 않는다.

3. 보호된 임시 터널 구성

--allowed-mail을 지원하는 경우 다음 구조로 실행한다.

cloudflared tunnel \
  --url http://127.0.0.1:8501 \
  --allowed-mail "AUTHORIZED_EMAIL@example.com"

위 이메일 주소는 예시다.

실제로는 사용자가 지정한 허용 이메일 주소만 사용한다.

실제 승인된 이메일 주소가 없으면 임의로 만들어 넣지 않는다.

사용자가 사용할 이메일과 미팅 시연 담당자 이메일만 접근 허용 대상으로 설정한다.

중요: --allowed-mail 없이 만든 Quick Tunnel을 보안 완료 상태로 보고하지 않는다.

정식 Cloudflare Access 설정을 사용하는 경우에는 해당 애플리케이션의 허용 정책과 적용 여부를 실제로 검증한다.

4. 서버 및 세션 보안 최종 확인
A. 관리자 비밀번호

과거 보고서에 노출된 비밀번호가 더 이상 유효하지 않은지 확인한다.

코드에서 제거한 사실만으로 비밀번호 교체 완료를 주장하지 않는다.

관리자 비밀번호가 교체되지 않았다면 외부 공개를 중단한다.

B. 로그인 세션

다음을 확인한다.

HTTPS 환경의 세션 쿠키 Secure 속성

HttpOnly 적용

적절한 SameSite 정책

세션 만료 및 로그아웃

상태 변경 요청의 CSRF 위험

외부 URL에서 로그인 후 세션 유지

C. 클라이언트 IP

CF-Connecting-IP를 무조건 신뢰하지 않는다.

신뢰할 수 있는 Cloudflare 경유 요청에서만 사용하고, 직접 접근 요청에서 클라이언트가 임의 설정한 헤더를 신뢰하지 않도록 수정한다.

헤더 위조가 로그인 횟수 제한을 우회하지 못하는지 검증한다.

D. 로컬 서버

가능하면 웹 애플리케이션을 127.0.0.1에만 바인딩한다.

DB와 내부 관리 포트를 외부에 직접 노출하지 않는다.

5. 외부 실접속 테스트

독립된 외부 네트워크에서 테스트한다.

동일 컴퓨터의 localhost 접속은 외부 테스트로 인정하지 않는다.

TEST A. 허용되지 않은 방문자

접근 허용 목록에 없는 사용자로 외부 URL에 접속한다.

기대 결과:

ACCESS_DENIED

TEST B. 허용된 이메일

허용된 이메일로 접근하여 OTP 인증을 완료한다.

기대 결과:

EMAIL_AUTH_SUCCESS

TEST C. 차마트 로그인

이메일 인증을 통과한 사용자가 차마트 자체 로그인에도 성공한다.

기대 결과:

APP_LOGIN_SUCCESS

TEST D. 외부 업무 시연

외부 브라우저에서 다음 기능을 실제 실행한다.

차량 목록 조회

데모 차량 등록

재고 상태 변경

데모 고객 등록

상담 기록 저장

영상 프로젝트 생성

화면 새로고침 후 데이터 유지 확인

기대 결과:

REMOTE_CRUD_PASS

TEST E. API 직접 접근

미인증 요청으로 고객, 거래, 서류 API에 직접 접근한다.

기대 결과:

HTTP_401_OR_ACCESS_DENIED

TEST F. 접속 종료

cloudflared 프로세스를 종료한 뒤 외부 URL의 접근이 차단되는지 확인한다.

기대 결과:

TUNNEL_CLOSED

TEST G. 모바일 UI

모바일 브라우저에서 로그인, 차량 목록, 고객 등록, 영상 프로젝트 화면이 정상 표시되는지 확인한다.

기대 결과:

MOBILE_UI_PASS

테스트가 실제로 불가능하면 해당 항목은 PENDING으로 보고한다.

6. 시연용 데이터 격리

외부 테스트는 데모 DB에서만 수행한다.

data/chamart/chamart_platform_demo.db

실제 고객정보나 계약서 사진을 외부 시연에 사용하지 않는다.

실제 딜러 거래 데이터:

REAL_DATA_0

상태 유지.

실제 운영 데이터베이스, 기존 정부 통계, 엔카 파일럿 원본을 수정하지 않는다.

7. 사용성을 위한 최소 실행 절차

사용자가 매번 복잡한 터미널 명령을 입력하지 않도록 로컬 시연 실행 스크립트를 준비한다.

필요한 동작:

환경변수 및 필수 설정 확인

웹 서버 기동

관리자 인증 설정 확인

인증이 적용된 터널 실행

브라우저 접속 URL 표시

서버·터널 종료 처리

단, 허용 이메일을 설정하지 않았거나 인증 보호를 활성화할 수 없다면 터널을 시작하지 않는다.

비밀번호, 터널 인증 토큰 등을 로그에 노출하지 않는다.

실제 인증 설정이 없는 상태에서 DEMO_READY를 표시하지 않는다.

REMOTE_DEMO_VERIFIED / ACCESS_PROTECTED / DEMO_ISOLATED
