# CHA-FICIAL DIRECTIVE 050 ADDENDUM
## MASTER VEHICLE REGISTRATION & MULTI-PLATFORM PUBLISHING READINESS

**추가 우선순위: P0**

기존 DIRECTIVE 050의 엔카 소싱 안정화 작업과 함께, 향후 차량의 다중 플랫폼 자동 등록을 위한 **차마트 통합 차량 마스터 입력 시스템**을 구축한다.

### 1. 차량 등록 화면 전면 확장

현재 단순 차량 등록 모달을 실제 중고차 딜러가 사용 가능한 전문 등록 화면으로 확장한다.

필수 영역:

1. 차량 기본 제원: 차량번호, VIN, 제조사, 모델, 세부 등급, 연식, 최초등록일, 배기량, 연료, 변속기, 구동방식, 차체 유형, 주행거리, 색상
2. 옵션: 표준 옵션 코드와 선택형 체크리스트, 순정·추가 장착 구분, 확인 상태
3. 사고·보험·성능: 사고·교환·수리·침수·누유, 주요 장치 점검 결과, 공식 증빙 서류
4. 사진: 외관, 실내, 계기판, 엔진룸, 하자 부위, 대표 사진, 정렬 순서
5. 가격·판매: 광고가, 매입가, 상품화 비용, 판매 상태, 딜러·상사 및 전시장 위치, 판매 조건
6. 광고 상세 설명: 차량 특장점, 고지사항, 차량별 소개문, 플랫폼별 문구
7. 권한·승인: 차량 소유·판매 권한, 사진 사용 권한, 외부 광고 승인
8. 플랫폼 연동: 플랫폼별 필수 필드 검증, 등록 상태, 매물 ID, 오류 원장

### 2. 데이터 구조 표준화

차량 원본 마스터와 외부 플랫폼별 광고 데이터를 분리한다.

- VehicleMaster: 차량 고유 사실 데이터
- VehicleOptions: 구조화된 옵션 목록
- VehicleCondition: 점검 및 사고 상태
- VehicleMedia: 실제 차량 사진과 사용 권한
- VehicleSalesProfile: 광고가, 판매 조건, 설명
- PlatformListing: 외부 플랫폼 ID, 등록 상태, 마지막 동기화 결과

차량의 원본 정보가 여러 플랫폼 간에 불일치하지 않도록 한다.

UNKNOWN과 미확인 값을 실제 사양으로 자동 변환하지 않는다.

### 3. 정확한 차종 및 트림 선택

제조사 → 차종 → 세대 → 연식 → 세부 트림 → 엔진/연료/구동방식의 단계별 선택 구조를 만든다.

차량번호 또는 VIN을 활용한 자동 정보 채우기는 적법한 조회 경로가 확보된 경우에만 구현한다.

자동 입력값도 관리자가 실제 서류와 비교하여 확인할 수 있어야 한다.

### 4. 플랫폼별 필드 매핑

향후 연결할 플랫폼:

- ENCAR
- KB_CHACHACHA
- CAR_MANAGER
- 추가 제휴 플랫폼

플랫폼마다 필수 필드, 선택 옵션, 사진 조건, 입력값 코드가 다를 수 있으므로 별도의 매핑 어댑터를 개발한다.

등록 전 검증 기능:

- 미입력 필수 필드 표시
- 지원하지 않는 옵션 코드 확인
- 실제 차량 사진 확인
- 사고·성능 정보 검증
- 딜러 권한 확인
- 플랫폼별 등록 가능 여부 표시

### 5. 게시·수정·삭제 연동 구조

상태를 다음과 같이 분리한다.

DRAFT → DATA_VERIFIED → READY_TO_PUBLISH → APPROVED → PUBLISHED → UPDATED → SOLD / UNPUBLISHED

공식적으로 허용된 API 또는 제휴 연동이 확인된 플랫폼만 실제 게시 기능을 활성화한다.

인증되지 않은 플랫폼에는 임의로 차량을 게시하지 않는다.

단, 게시용 데이터 생성·필수 정보 검증·플랫폼별 내보내기 및 수동 등록 지원 기능은 먼저 구현할 수 있다.

### 6. 실제 딜러 시나리오 테스트

장한평 파트너의 허가된 차량 1대를 대상으로 다음 시나리오를 검증한다.

차량 정보 입력 → 옵션 선택 → 점검 서류 등록 → 사진 업로드 → 판매가 등록 → 광고 설명 작성 → 플랫폼별 등록 준비 검사

정보를 수정하면 원본 마스터와 플랫폼별 게시 준비 데이터에 올바르게 반영되는지 검증한다.

실제 등록 API가 없다면 게시 성공이라고 보고하지 않는다.
