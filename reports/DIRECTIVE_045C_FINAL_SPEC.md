발견한 보완 사항 두 가지

첫째, CF-Ray가 있다는 이유만으로 요청을 신뢰하면 안 돼.

CF-Ray는 Cloudflare 요청을 식별하기 위한 HTTP 헤더이지, 암호학적으로 검증된 인증서가 아니야. 직접 접근 가능한 경로에서 동일한 이름의 헤더를 만들어 보낼 수 있으므로, 단순한 존재 확인만으로 클라이언트 IP나 HTTPS 여부를 판단하는 것은 불완전해. 
Cloudflare Fundamentals docs

차마트 웹사이트를 127.0.0.1에만 바인딩한 것은 좋은 조치야. 추가로 앱의 공개 접속 모드와 신뢰 프록시 설정을 명시적으로 고정하는 편이 안전해.

둘째, 9/9 PASS와 외부 시연 PASS는 별도로 평가해야 해.

현재 9개 테스트에는 허용하지 않은 이메일의 실제 차단, 허용된 이메일의 PIN 인증, 외부 기기에서 차량 등록이 포함되지 않았어.

그러므로 현재 공식 상태는 제미나이가 보고한 그대로 유지하는 게 맞아.

ACCESS_PROTECTED_CONFIGURED / REMOTE_TEST_PENDING

보호 설정과 터널 연결은 확인됐다고 보고됐지만, 실제 보호 동작까지 검증됐다는 의미는 아니야.

이후 신규 기능 개발은 중지한다.

1. 프록시 신뢰 처리 점검

CF-Ray 헤더 존재 여부만으로 요청의 진위, 실제 IP 또는 HTTPS 연결 여부를 확정하지 않는다.

로컬 서버는 127.0.0.1 전용 바인딩을 유지한다.

로그인 횟수 제한과 세션 쿠키의 보안 정책은 명시적인 배포 설정 및 신뢰 가능한 프록시 경로를 기준으로 처리한다.

실제 환경에서 헤더 위조로 보안 판단을 변경할 수 없는지 확인한다.

2. 미팅용 원클릭 실행 절차 완성

scripts/run_chamart_demo.sh

시연에 사용할 이메일이 실제로 접근 가능한 주소인지 사용자가 확인할 수 있도록 안내한다.

3. 실제 외부 접속 수동 검수

사용자가 휴대전화의 모바일 데이터망 또는 별도 외부 네트워크에서 직접 확인할 수 있도록 다음 체크리스트를 제공한다.

허용되지 않은 이메일은 차단되는가?

허용된 이메일로 OTP를 실제 수신하는가?

OTP 입력 후 차마트 로그인 화면에 도달하는가?

관리자 로그인이 성공하는가?

데모 차량을 등록할 수 있는가?

데모 고객과 상담 기록을 저장할 수 있는가?

차량 영상 프로젝트를 생성할 수 있는가?

새로고침 후 데이터가 유지되는가?

터널 종료 후 외부 접속이 끊어지는가?

실제 검수 결과가 없는 항목은 PENDING으로 표시한다.

4. 이후 개발 동결

실제 고객정보나 계약서를 외부 시연에 사용하지 않는다.
