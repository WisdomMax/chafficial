## 1. P0-1 사고·보험·성능 데이터 위조 가능성 제거
- **대상**: `src/chaficial/platform/db.py` / `init_demo_db()`
- **문제점**: 빈 `accident_history_json`에 CLEAN, NONE, 카히스토리 검증 완료 날짜를 자동 삽입하는 로직 존재. 데모 시딩 목적이라도 실매물 원장에서는 허용 불가.
- **수정 지시**:
  1. 사고·보험·성능점검 결과가 비어 있으면 `UNCHECKED` 또는 `UNKNOWN`으로 엄격 유지.
  2. `CLEAN`, `NO_ACCIDENT` 등의 확정 상태는 검증된 증빙이 존재할 때만 기록.
  3. 실데이터에 가상의 검사기관, 검사일자, 등급, VIN, 옵션을 자동 부여하지 않음.
  4. 데모 전용 데이터는 명확한 `is_demo=True` 및 데이터 출처 유지.
  5. 기존 데이터를 조사하여 해당 자동 보정으로 작성된 의심 레코드를 별도 감사 목록으로 추출.
  6. 실제 검증된 값은 삭제하거나 덮어쓰지 않고, 출처 불명의 값은 검증 대기 상태로 격리하고 수정 이력 보존.
- **완료 기준**: 미확인 차량에 대해 서버를 여러 번 재시작해도 무사고·정상점검 상태가 자동 생성되지 않아야 함.

## 2. P0-2 RL Reward 임의 확정 차단 (Ground Truth 강제)
- **대상**: `src/chaficial/platform/service.py` / `update_rl_reward()`
- **문제점**: 클라이언트 요청의 `fee_revenue`, `operating_cost`, `days_to_sell` 등을 그대로 받아 즉시 보상 계산. 실제 거래 원장과의 연결 증빙 검증 부재.
- **수정 지시**:
  1. 실제 판매 계약 및 정산 확인 없이는 검증된 Reward를 확정하지 않음.
  2. Reward 갱신은 거래 ID(`transaction_id`) 및 정산 ID를 기준으로 수행.
  3. 계약 상태, 실제 수수료, 운영비용, 정산 완료 여부, 기여 증빙을 서버 DB에서 직접 재조회(Ground Truth).
  4. `is_demo=True`인 거래는 실전 보상 데이터에서 제외.
  5. 보상 확정 시점과 증거 식별자(`verified_transaction_id`)를 기록.
  6. 동일 정산에 대한 반복 요청이 이중 보상으로 누적되지 않도록 방지.
  7. 과거 Reward 변경 시 기존 기록 보존 및 정정 이력 추가.
  8. 계약 기여도를 확인할 수 없으면 `UNCERTAIN` 상태로 유지.
  9. 비용만 발생하고 아직 판매가 이루어지지 않은 차량의 상태와 보상 구분.
- **완료 기준**: 임의의 숫자를 POST하는 것만으로 `is_censored=False` 및 검증된 Reward가 기록되어서는 안 됨.

## 3. P0-3 Propensity 및 학습 데이터 분할 정정
- **대상**: `evaluate_rl_decision()` / `RLDecisionLog`
- **문제점**: 0.88, 0.92 등 임의 고정값을 Propensity로 저장. 결정론적 규칙 정책의 실제 확률은 1.0임. 또한 `now.month >= 10` 기준으로 분할하여 TEST 집합 미생성 및 연도 미반영.
- **수정 지시**:
  1. 규칙 기반 결정론 정책은 실제 행동 선택 확률 `1.0`을 기록.
  2. 확률적 정책은 실제 행동 분포(Softmax 등)에서 계산한 확률만 기록.
  3. 확률을 알 수 없는 과거 데이터는 `PROPENSITY_UNKNOWN`으로 격리.
  4. 행동별 선택 가능 여부와 당시 권한·예산 제약 저장.
  5. 시간순 분할을 월 기준에서 실제 결정 타임스탬프(`timestamp`) 기준으로 수정: 사전에 확정된 기준 일자(Train / Val / Test 3단계 구간) 적용.
  6. 동일 물리 차량의 반복 의사결정 및 결과가 분할 간 누출되지 않게 점검.
  7. 현재 마스터 데이터를 이용해 과거 State를 재구성하는 행위 금지.
  8. State는 당시 관측·적재가 완료된 정보만 사용해야 하며, `observed_at`과 `ingested_at`을 모두 검사.
- **완료 기준**: 시간 경계, 차량 중복, 사후 입력 정보, 선택 확률에 대한 독립 테스트 통과.

## 4. P0-4 실적 및 ROI 집계 공식 수정
- **대상**: `get_attribution_summary()`
- **문제점**: 이미 `chamart_net_profit`에 운영비가 차감되어 있는 상태에서 ROI 계산 시 운영비를 이중 차감할 위험. 데모 거래를 실제 계약처럼 집계하거나 시딩에서 임의로 `AI_VIDEO`로 변경하는 문제.
- **수정 지시**:
  1. 실제 실적 집계에서 `is_demo=True`를 완전히 제외.
  2. `is_verified_sale=True`, 정산 완료, 검증 가능한 계약 및 비용 증빙 확인.
  3. 공헌이익 정의를 단일 공식으로 통일: 총 광고 매출, 딜러 수수료, 총 운영비용, 순공헌이익을 명확히 구분.
  4. 모든 금액에 명확한 원화 단위(`단위: 만원`) 및 스키마 정의 부여.
  5. ROI는 중복 비용 차감 없이 계산: `ROI = (순공헌이익 / 총운영비) * 100` (순공헌이익이 이미 운영비 차감 후라면 `(순공헌이익 / 총운영비) * 100` 또는 총수수료매출 대비 명확한 공식 규정).
  6. 분모(운영비)가 0인 경우 산출 불가(`NOT_AVAILABLE`)로 표시 (임의의 0% 왜곡 금지).
  7. 유입 채널 문자열만으로 광고 기여 계약 확정 금지.
  8. 실거래 0건이면 실전 ROI는 `NOT_AVAILABLE`로 표시.
  9. 데모 ROI 525.0%는 실제 사업 성과가 아님을 UI와 API에 명확히 표기.

## 7. 강화학습 운영 준비도 판정 재설계
- **문제점**: 단순 50건 Bandit, 500건 CQL 기준은 과학적 근거 부족.
- **평가 지표 재설계**:
  1. 증빙이 있는 실제 의사결정 수
  2. 실제 종결 및 관측 중인 결과 수
  3. 행동별 선택 표본 및 비검열 표본의 대표성
  4. 정책별 선택 확률 신뢰도 (Propensity Score 신뢰성)
  5. 행동 간 비교 가능성 및 분포 중첩 (Common Support)
  6. 시간순 검증 구간 (Train/Val/Test 분할 완전성)
  7. 비용·수수료 데이터 완전성 및 유효 계약 연결률
  8. 데이터 누출 검사 결과
- **상태 판정**: 데모 레코드는 RL 준비도 판정에서 제외하며, 현재 상태는 `PENDING_REAL_WORLD_DATA_COLLECTION` 유지.
