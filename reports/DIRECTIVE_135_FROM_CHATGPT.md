# CHA-FICIAL DIRECTIVE 135
## 카매니저 실시간 수집과 차마트 D1 동기화 단절 복구

**기준 커밋:** `59cee88`  
**우선순위:** P0  
**기존 DIRECTIVE 134 판정:** 안전성 일부 개선, 실시간 동기화 완료 미승인

---

### 핵심 목표
수집 프로그램, 동기화 프로그램, 공개 승인 시스템이 각각 존재하지만 실제로 이어져 움직이지 않고 있는 단절을 복구한다.  
36대라는 숫자를 맞추기 위해 임의 데이터를 공개하지 않는다. 다만 실제 데이터가 계속 동기화되는 시스템을 반드시 완성한다.

---

### TASK 1. 실시간 수집기 직접 연결
- 기존 `JanghanpyeongCollector` 및 `CarManagerLiveClient`를 재사용하여 `ContinuousSyncDaemon`이 카매니저에서 최신 자료를 직접 받아오도록 변경한다.
- 기존 JSON 파일을 새로 수집한 것처럼 보고하지 말 것.
- 실제 원본 수집 시간, 성공 여부, 차량 수 기록.
- 수집 실패 시 기존 정상 데이터 보존.
- 정기 실행, 재부팅 후 자동 복구, 오류 재시도 검증.

---

### TASK 2. 실제 동기화 활성화
- `run_forever()`의 강제 `dry_run=True` 제거.
- `DRY_RUN` 결과는 성공적으로 전송된 동기화 체크포인트로 저장하지 말 것.
- 실제 서버 응답을 확인한 경우에만 마지막 성공 상태 갱신.
- 오류 이후 재시도 시 누락 없이 전송되는지 검증.
- Mac mini launchd의 실제 실행 상태와 로그 제출.

---

### TASK 3. 원본 ID 기반 61대 연결
- 전체 번호판이 없는 차량도 검증된 카매니저 고유 ID로 비공개 적재 가능하도록 서버와 클라이언트 규약 통일.
- 실제 전체 번호판이 없으면 `null` 유지.
- 카매니저 매물 ID, 제시번호, 상사 ID를 구분하여 저장.
- 원본 식별자가 없거나 중복될 때는 격리.
- 임의 번호판이나 가상 제원 생성 금지.

---

### TASK 4. 판매·사진 권한과 동기화 분리
- 비공개 데이터 수집은 계속 진행.
- 실제 상사 광고 동의의 범위·유효기간 및 사진 사용 권한을 증빙 기반으로 관리.
- 증빙 확인 없이 `marketing_consent_verified=1` 일괄 부여 금지.
- 마이그레이션에서 확인되지 않은 다른 상사를 일괄 `INACTIVE` 처리하지 말 것.
- 이미 보호된 `64노3143`은 사용자 별도 승인 전까지 비공개 유지.
- 판매가 미확정 차량은 계속 비공개.
- 신규 공개는 관리자 승인 워크플로를 통해서만 수행.

---

### TASK 5. 단일 엔드투엔드 합격 시험
운영 자료를 훼손하지 않는 격리 환경에서 다음 경로를 실제 실행한다:
1. 카매니저 최신 조회 → 원본 ID 매칭 → 변경 감지 → D1 전송 → 데이터 일치 확인 → 두 번째 조회에서 변경 없음 확인.
2. 그다음 원본 가격 또는 판매 상태를 통제된 테스트 데이터에서 변경하여 변경분만 갱신되는지 확인한다.

**합격 보고에 반드시 포함할 수치:**
1. 실제 카매니저에서 새로 조회한 차량 수
2. 원본 ID 기준으로 정상 매칭한 수
3. D1 신규 등록·갱신·건너뜀·실패 수
4. 최초 전송 이후 두 번째 무변동 전송 결과
5. 공개 가능한 판매 승인 차량 수
6. 현재 실제 공개 차량 수
